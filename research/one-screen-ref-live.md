# 한 화면(스크롤 없음) 대시보드 레퍼런스 조사: 실제 운영 서비스 편

- 조사 일자: 2026-10-07
- 범위: 실제 운영 중인 웹 서비스 중 정보 밀도가 높아 여러 섹션 목록이 한 화면에 보이는 곳(금융·시장 대시보드, 뉴스 집계, 실시간 인텔리전스 보드 등)
- 대상 SPEC: 6개 뉴스 섹션 x Top 5 = 이슈 30개, 이슈당 순위·제목·AI 3줄 요약·연관기사 수·원문 링크·북마크, 데스크톱(1920x1080, 1440x900)에서 스크롤 없이 한 화면

## 검증 방법과 한계

- 각 후보의 공식 og:image, 공식 블로그·GitHub 문서의 스크린샷을 `curl -L`로 받아 Read 도구로 직접 확인했다(저장 위치는 scratchpad의 `onescreen-live\`).
- 한계 1: 라이브 사이트를 브라우저로 직접 열어 보지 못했다. 이미지는 마케팅/블로그용 캡처라 실제 뷰포트 크기와 다를 수 있다(예: Koyfin 이미지는 1200x630으로 축소된 2022년 캡처).
- 한계 2: 대부분의 og:image는 로고·홍보 이미지여서 레이아웃 판단에 쓸 수 없었다(TradingView, World Monitor og, Naver/Daum 등). 이런 곳은 "미확인"으로 표시했다.
- 한계 3: 뉴스 집계 사이트(Techmeme, Memeorandum, Google News, Naver 뉴스홈 등)는 스크린샷 이미지를 확보하지 못했다. 사전 지식으로만 아는 부분은 "미확인(추정)"으로 표기하고 추천 근거로 쓰지 않았다.
- 실제 한 화면 여부 판정은 "이미지에서 프레임 안에 모든 패널이 완결되어 보이는가"를 기준으로 했다.

## 추천 1순위: Koyfin 마켓 대시보드

- URL: https://www.koyfin.com (앱 화면 캡처는 https://www.koyfin.com/wp-content/uploads/2022/10/Screenshot-2022-10-04-at-19.21.14.png, 이미지 확인)
- 개요: 투자 데이터 서비스의 홈 대시보드. 좌측 아이콘 사이드바 + 검색 바 + 본문의 카드형 패널 그리드.
- 그리드 구조(이미지 기준): 본문은 3열. 좌열은 패널 3개(U.S. Equity Markets, U.S. Equity Sectors, Fixed Income), 중앙열은 Market News(3줄) + Normalized Performance 차트 + 하단 US Equity Factors, 우열은 Currencies, Global Markets, Commodities. 하단에 좌/중/우가 이어지는 패널 높이를 맞춰 프레임 바닥에서 깔끔히 끝난다. 이미지에서 모든 패널이 잘림 없이 한 프레임에 들어간다(단 Commodities, Fixed Income 하단 행은 프레임 가장자리에서 끝남).
- 항목 1개당 높이·정보량: 1200x630 이미지 기준 표의 행 높이는 약 19px(이미지는 축소본이라 실제 CSS 행 높이는 알 수 없고, 비율상 약 24~30px로 추정). 한 행에 티커, 가격, 변화, 변화율 4가지 정보. 패널 제목 줄 약 20px(이미지 기준) + 소제목 줄.
- 한 화면에 담는 기법:
  - 패널을 3열 고정 그리드로 나누고, 패널별로 필요한 행 수만큼만 노출(행 수 고정)
  - 작은 글꼴(이미지 기준 약 8~9px, 실제 약 12px 추정)과 얇은 행, 밝은 구분선 대신 옅은 배경
  - 패널 제목 우측에 "확대/전체보기" 아이콘으로 상세는 별도 화면으로 이동
  - 뉴스는 제목 한 줄 + 출처 + 시각만 노출(Market News 3줄)
  - 사이드바는 아이콘만 두어 가로 공간 절약
- SPEC 30개 카드 적용 방법: 6개 섹션 패널을 3열 x 2행으로 배치. 각 패널은 헤더(섹션명, 전체보기 아이콘) + 이슈 5행. 이슈 행은 순위, 제목(1줄 말줄임), 연관기사 수 배지, 링크/북마크 아이콘. AI 3줄 요약은 행 안에 작게 상시 노출하거나(1920 기준) 호버로 펼친다.
- 가져올 부분: 3열 패널 그리드, 패널 높이 균등 분할, 패널 헤더의 전체보기 아이콘, 아이콘 전용 사이드바, 얇은 구분 + 작은 글꼴 시스템
- 맞지 않는 부분: 항목이 숫자 위주라 행 높이가 낮음. SPEC은 항목당 AI 3줄 요약이 있어 행이 훨씬 높아짐. 또한 SPEC은 사이드바가 필요 없음. 이미지가 2022년 캡처라 현재 UI와 다를 수 있음.

## 추천 2순위: Finviz

- URL: https://finviz.com (이미지 근거: https://finviz.com/blog/a-new-era-for-news-on-finviz 의 스크린샷, 확인)
- 개요: 주식 스크리너/뉴스/히트맵 서비스. 매우 높은 밀도의 한 줄 목록과 호버 상세가 특징.
- 그리드 구조(이미지 기준): 상단 로고+검색+버튼 바(약 90px), 메뉴 탭 바(약 60px), 시간 표시 줄, 그 아래 본문. 스크리너 화면은 20행 표, Market Pulse 뉴스는 약 25행의 한 줄 목록. Daily Digest는 우측 오버레이 패널(차트 + 헤드라인 + 불릿 요약). 홈 대시보드 화면 전체는 이미지로 확인하지 못했다.
- 항목 1개당 높이·정보량: 뉴스 한 줄 약 50px(2000px 폭 캡처, 즉 CSS 약 25px). 한 줄에 시간 경과, 아이콘, 헤드라인, 종목 배지(등락률 색), "More +" 링크. 스크리너 행은 약 40px(캡처 기준) 에 10개 열.
- 한 화면에 담는 기법:
  - 헤드라인을 한 줄로 고정하고 넘치면 말줄임(이미지에서 "..."로 잘린 행 확인)
  - 종목/등락률을 색 배지로 압축
  - 상세는 행 호버 시 툴팁(차트 + 회사 정보 + "AI-generated" 요약 3줄 정도)으로 숨김(이미지 확인)
  - "More +"로 행 확장
  - 필터 드롭다운으로 목록 축소
  - 어두운 테마로 밀도를 높이면서 가독성 유지
- SPEC 적용 방법: 카드 기본 상태는 한 줄(순위, 제목, 연관기사 수 배지, 아이콘). AI 3줄 요약은 호버 툴팁 또는 "More +" 확장 행으로 노출. 6개 섹션 패널 각각이 5행 한 줄 목록이면 한 화면 확보가 쉽다.
- 가져올 부분: 한 줄 행 + 호버 AI 요약 툴팁(AI 생성 고지 문구 포함), 배지형 메타, 행 확장 패턴
- 맞지 않는 부분: 호버는 터치 환경에서 쓸 수 없음(모바일은 세로 스택이라 문제 없음). 요약이 항상 보이지 않아 "요약이 핵심 가치"인 SPEC에서는 정보 접근성이 낮아짐. 단일 목록 중심이라 6패널 그리드 레이아웃 근거로는 약함. 홈 한 화면 완결 여부는 미확인.

## 추천 3순위: World Monitor

- URL: https://www.worldmonitor.app (이미지 근거: https://github.com/koala73/worldmonitor 의 docs/images/worldmonitor-7-mar-2026.jpg, 확인)
- 개요: 오픈소스 실시간 글로벌 상황판. 헤더 + 대형 지도 + 하단 다열 패널(Live News, Live Webcams, AI Insights, AI Strategic Posture).
- 그리드 구조(이미지 기준): 최상단 헤더 바(약 50px, 로고/라이브 표시/드롭다운/검색/설정), 제목 바, 지도(높이 약 560px), 그 아래 패널 행(높이 약 560px)에 4개 패널(좌 2칸 폭 Live News, 중앙 2칸 폭 Webcams, 우측 AI Insights와 AI Strategic Posture 세로 스택). 이 아래로 패널 행이 한 줄 더 이어지는 것이 이미지 하단에서 보임(잘림). 즉 한 화면 완결은 아님.
- 항목 1개당 높이·정보량: AI Insights 카드 하나가 약 250px(캡처 기준)에 6~7줄 요약 포함. 정보량은 많지만 한 카드가 크다.
- 한 화면에 담는 기법: 패널 고정 높이 + 패널 내부 탭 칩(BLOOMBERG, SKYNEWS 등, IRAN ATTACKS/ALL/MIDEAST 등), 패널 우상단 전체화면 버튼, 긴 요약은 카드 안 말줄임/내부 스크롤, 이질적 정보를 그리드 영역으로 분리.
- SPEC 적용 방법: 패널마다 고정 높이를 주고 헤더 우측에 전체화면 아이콘을 둔다. 패널 상단 탭 칩 패턴은 SPEC에서는 필수가 아니지만, 한 화면에 못 담을 때 "섹션 패널 2개씩 탭 전환" 같은 대안으로 쓸 수 있다.
- 가져올 부분: 어두운 대시보드 테마, 패널 헤더 + 전체화면 버튼, 패널별 LIVE/갱신 표시 배지(SPEC의 마지막 갱신 시각 표시에 응용)
- 맞지 않는 부분: 지도가 화면의 절반을 차지, 패널 일부는 화면 밖으로 이어짐, 3D/지도 위주라 텍스트 카드 30개에는 과함.

## 최종 1순위와 이유

Koyfin 방식(3열 패널 그리드, 패널 높이 균등 분할, 작은 글꼴)을 골격으로 하고, Finviz의 한 줄 행 + 호버/확장 AI 요약 패턴을 보완 장치로 쓰는 조합을 권한다.

이유: 이미지로 확인한 후보 중 패널이 프레임 안에서 완결되는 것은 Koyfin이 유일했다(Finviz와 World Monitor는 모두 하단으로 이어짐). SPEC의 6개 섹션 패널은 Koyfin의 3열 그리드와 구조가 같다. 다만 Koyfin은 항목당 정보량이 작아, 항목당 3줄 요약이 필요한 SPEC에서는 카드 높이를 따로 계산해야 한다.

## 1920x1080 기준 SPEC 배치 제안(픽셀 예산)

가정: 브라우저 뷰포트 높이는 약 940~970px(브라우저 UI 제외)가 현실적이므로, 1080 전체가 아니라 약 950px를 쓴다고 보고 계산한다. (뷰포트가 1080에 가깝다면 카드 높이를 약 10px 키울 수 있다.) 아래 수치는 설계 제안이며 검증된 값이 아니다.

- 헤더: 높이 56px(로고, 날짜 선택기, "오늘" 버튼, 마지막 갱신 시각, 로그인/북마크 메뉴)
- 본문 여백: 상하 12px, 패널 간격 12px
- 본문 가용 높이: 950 - 56 - 24(상하) - 12(행 간격) = 약 858px, 패널 높이 약 429px x 2행
- 가로: 1920 - 좌우 여백 32 - 열 간격 24 = 1864, 패널 폭 약 621px x 3열
- 패널 구성: 헤더 36px(섹션명, 전체보기 링크) + 이슈 5개 = 약 393px, 이슈당 약 78px
- 카드(78px) 구성:
  - 1행(22px): 순위 번호 + 제목 14px 한 줄 말줄임 + 우측에 연관기사 수 배지, 링크 아이콘, 북마크 아이콘
  - 2~4행(3 x 16px = 48px): AI 요약 12px, 줄 높이 16px, 3줄. 각 줄을 한 줄 말줄임으로 고정해 높이 불변
  - 패딩 상하 약 4px 정도로 매우 빡빡함. 여유가 없으면 아래 대안 사용
- 대안 A(여유 확보): 요약은 기본 1~2줄만 보이게 하고 호버/클릭 시 3줄을 툴팁 또는 확장으로 노출(Finviz 방식). 이 경우 카드 높이를 약 64px로 줄일 수 있다.
- 1440x900 대응: 뷰포트 약 780px 가정 시 패널 높이 약 345px, 카드 약 61px, 요약은 1줄 + 호버 펼침으로 전환. 3열이 너무 좁아지면(패널 폭 약 460px) 폰트를 12px에서 유지하되 제목 한 줄 길이 제한 필요.
- 모바일: 6개 패널 세로 스택, 스크롤 허용, 카드 요약 3줄 상시 노출.
